# 卡 8：原始前端恢复与真实接口接入

用户已确认本方案。基线 main：8e589eb0c1a98ef87857bdc8d0ea21d9db717c0c。

## 设计依据

以用户提供的 epal-gaming-companion.zip 内 src/ 为视觉和交互底稿。
原始 App.tsx 声明并渲染 48 个页面。恢复页面、入口、底部导航、转场、
首页搜索/三分类/Trending Realms/Legend/New/More、英文和阿语 RTL。
主题为 #0f071a 深紫。移除绿/沙/金改版，不把任何原始假业务数据带回来。

## 实现边界

- 将原始 JSX 和原始组件作为展示层底稿；以可追踪提取方式保留页面结构。
- 保留现有 AppProvider、登录鉴权、admin、shared 游戏目录和货币政策。
- 原版可保留视图/表单/弹窗状态；账号、钱包、订单、聊天、评价、审核状态
  必须由现有后端返回，不能由原版本地模拟逻辑产生。
- 使用现有 businessApi 与必要的前端适配层，不导入原版 mock server.ts。
- 游戏及在线数来自 GET /api/games；陪玩来自 GET /api/companions。
- Legend / New 可使用后端排行榜 poolTag；无对应真实记录则显示空状态，
  不在前端伪造门槛、评分、标签或排名。
- 钱包和套餐来自真实接口及政策快照，默认 $1=100 币；不写死新汇率。
- 订单、REST 聊天和轮询、评价、申请和审核全部使用现有真实接口。
- 缺接口的社区、破冰、任务/等级、社交统计等保留页面与明确真实空状态；
  不新增规则，不模拟成功写入，不修改后端以填满界面。
- 图片用真实上传头像、现有真实游戏封面或本地缺省资源，加载失败兜底。
- client 中不存在原版假人物、假帖子/订单/评价、picsum/Unsplash 外链、
  固定在线人数；包括不再使用的旧文件也不能残留上述内容。

## 验收

1. pnpm lint、pnpm test（原 45 项全部普通通过）、pnpm validate、pnpm build。
2. 首页、游戏详情、陪玩详情、社区、消息列表/聊天、Me、钱包/充值、申请、
   设置分别英文/阿语实跑截图；与原版结构和配色核对，非只检查编译。
3. 恢复界面里实跑注册登录、$1 沙盒充值到账100、完整订单、聊天收发、
   评价、申请→后台审核→公开上架。只用独立临时存储和明确 LOCAL 账号。
4. 最终静态扫描禁止内容和旧主题残留；检查48个原始页面均有可达入口。
5. 一个 PR，基于当前 main，不自动合并，不改真实资金记录。

## 架构取舍

采用原始展示层 + 已有真实状态/接口适配层。单纯对当前30个路由换色不能
恢复缺失页面；直接运行原 App 会恢复模拟付款和假账号，均不满足本卡。
展示层按源码既有边界提取，业务真相只有当前后端一份。
